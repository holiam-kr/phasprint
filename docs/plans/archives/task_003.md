# task_003: 남은 리뷰 지적 14건 정리

## Goal

리뷰 rev.3의 미처리 14건(지적 4·5·6·7·8·9·10·12·13·15·16·17·18·19·20 중 처리분 제외)을 닫는다.
`task_002` 가 하네스의 **동작**을 고쳤다면, 이번은 **기록·규범·배포**다.

가장 급한 것은 지적 7이다. 지금 `.gitignore:2` 가 `docs/` 를 통째 제외해서 **리뷰 문서 20건과
계획서 3개가 이 머신에만 있다.** 세션이 끝나면 근거가 사라진다.

## Design

**택한 접근** — 위험도 순으로 6단계. 기록 보존(7·8)을 **맨 앞에** 둔다. 지금 근거가 커밋되지
않고 있어서, 이후 단계에서 무엇을 왜 바꿨는지 남길 자리가 없다.

**기각한 대안**

| 대안 | 기각 이유 |
|---|---|
| 타스크를 3~4개로 쪼갠다 | 14건 중 11건이 문서 한 줄~열 줄 변경이다. 쪼개면 계획서 승인 왕복이 작업보다 비싸다. 위험한 2건만 결정 지점으로 분리하는 편이 낫다 |
| `docs/` 를 전부 추적 | `docs/working/` 은 진행 중 부산물이라 노이즈. 산출물(`decisions/`·`plans/`)만 추적한다 |
| 중단 조건을 파일 하나로 추출해 훅이 읽게 | 훅은 Node, 스킬은 마크다운, README는 산문이라 형식이 다르다. 기계적 단일화보다 **정본 지정 + 나머지는 요약·참조**가 현실적이다 |
| 지적 9를 `.git` 탐색으로 해결 | 리포 루트를 찾는 건 맞지만 `docs/plans/` 가 리포 루트에 없을 수도 있다. `docs/plans/` 자체를 위로 훑는 편이 직접적이다 |

**결정이 필요한 2건** — 승인 시 함께 답해 주십시오.

1. **지적 5 — `Abbreviations` 항목 삭제**
   3일 전에 직접 요청하신 규칙이다. 삭제를 권하는 근거는 세 가지다. ① 판단 근거("사용자가
   축약어를 썼는가")가 대화 이력에만 있어 압축되면 소실된다 — 이번 세션이 실제로 압축됐다.
   ② core 8항목 중 발동 빈도 최고, 안전 영향 최저. ③ 474바이트로 Secrets(595) 다음으로 크고,
   매 세션 + 매 압축마다 주입된다. **유지를 택하시면 그대로 두고 지적 5를 "수용된 비용"으로
   닫겠다.**

2. **지적 19 — 계획서에 조건부 `## Design` 절**
   `task_001` 로 제안했다가 폐기하신 주제다. 다시 여는 근거는 OMC 대조다 — 40개 스킬을 가진
   하네스가 계획서에 ADR 절(Decision / Drivers / Alternatives / Why chosen / Consequences)을
   **별도 게이트 없이** 필수화한다. 다만 이미 한 번 기각하신 사안이므로 **기본값은 "하지 않음"**
   으로 두고, 원하실 때만 넣겠다. (참고: `task_002` 와 이 계획서는 그 형식을 이미 쓰고 있다.)

## Steps

### 1. 기록이 살아남게 한다 (지적 7·8)

- 산출물
  - `.gitignore` — `docs/` 통째 제외를 걷어내고 `docs/working/` 만 제외. `docs/plans/`,
    `docs/decisions/` 는 추적
  - `HANDOFF.md` — 루트에 실제 생성. 개요 / 완료 / 진행 중 / 다음 / 주의사항
  - `docs/decisions/` — `task_002` 의 결정(승인=디렉토리, 상태 머신 기각) 기록
- 검증
  - `git check-ignore -v` 로 `docs/plans/`·`docs/decisions/` 가 추적되고 `docs/working/` 만
    제외되는지 확인
  - `git status --short` 에 리뷰 산출물이 추가 대상으로 나타나는지 확인

### 2. 중복과 찌꺼기를 줄인다 (지적 12·13)

- 산출물
  - 중단 조건의 정본을 `skills/sprint/SKILL.md` §4로 지정. `core.cjs`·`finish-gate.cjs`·
    README 2종은 요약하되 **개수와 항목명이 정본과 일치**하도록 정리
  - `finish-gate.cjs` — 마커 디렉토리에서 7일 넘은 `.stop` 파일 정리 (실패해도 무시)
- 검증
  - 다섯 곳의 조건 개수·항목명이 일치하는지 grep
  - 오래된 마커를 만들어 두고 실행해 사라지는지, 최신 마커는 남는지 테스트 추가

### 3. core를 정리한다 (지적 4·5)

- 산출물
  - `hooks/core.cjs` — (승인 시) `Abbreviations` 삭제
  - `README.md`·`README.ko.md` — core 항목 나열 갱신
  - core 항목의 **추가·삭제 기준**을 README에 명문화: 모든 프로젝트에 적용되는 행동 규칙만
    core에 두고, 문서 요구·상황별 절차는 cycle로. 새 항목을 넣을 때 무엇을 뺄지 함께 정한다
- 검증
  - `node --test` 전건 통과 (core 테스트의 기대 항목 목록도 갱신)
  - `node hooks/core.cjs | wc -c` 로 절감량 실측

### 4. 스킬에 규범을 준다 (지적 6·18·20, 조건부 19)

- 산출물
  - 두 스킬 공통 섹션 구조: 목적 / 언제 쓰나 / **언제 쓰지 않나** / 절차 / 중단 조건 / 체크리스트
  - `investigate` — `Do_Not_Use_When`(오타·한 줄 수정 등 사소한 실패), `:12` 의 "재현 안 되면
    조사하지 마라" 모순 수정
  - `sprint` — 품질 기준 수치화(주장의 파일/라인 인용 비율, 수용 기준의 테스트 가능 비율)
  - (승인 시) 계획서 템플릿에 조건부 `## Design` 절 + 트리거
- 검증
  - 두 스킬에 동일 섹션이 존재하는지 grep
  - `investigate` 에서 모순 문장이 사라졌는지 확인

### 5. 훅과 커맨드를 넓힌다 (지적 9·10·17)

- 산출물
  - `hooks/lib/plans.cjs` — `docs/plans/` 를 cwd에서 위로 훑어 첫 번째를 채택 (탐색 상한 있음)
  - `commands/*.md` — OMC식 폴백 문장: 플러그인 경로를 직접 못 읽으면 설치 경로에서 찾아라
  - `skills/investigate/SKILL.md`·`commands/report.md` — 실행 출력을 옮길 때 시크릿 마스킹 상기
- 검증
  - 하위 디렉토리를 cwd로 주고 상위의 계획서를 찾는지 테스트 추가
  - 탐색이 홈 디렉토리 위로 올라가지 않는지 테스트 추가

### 6. 배포 정비 + 적대 리뷰 (지적 15·16)

- 산출물
  - `.claude-plugin/plugin.json` — `repository`·`homepage`·`license`·`keywords`, 0.5.0
  - `commands/*.md` description에 한국어 트리거
  - 리뷰 문서 rev.4로 상태 갱신
- 검증
  - `node --test` 최종 전건 통과
  - `node -e` 로 `plugin.json` 파싱
  - 적대 리뷰 보고

## Risks / unverified

- **지적 2는 이번에도 닫히지 않는다.** 원인 미확정 상태가 유지된다. 재발 시 `systemMessage` 로
  잡히기를 기다리는 중이다.
- **지적 17은 여전히 unverified.** 폴백 문장은 치환 실패에 대한 보험이지 확인이 아니다.
  확인은 `/plan` 을 실제 실행해야 가능하다.
- **지적 9의 상위 탐색은 부작용이 있다.** 하위 디렉토리에서 상위 리포의 계획서를 집으면,
  의도치 않은 리포의 계획서에 반응할 수 있다. 탐색 상한(리포 경계 또는 3단계)을 둔다.
- **지적 12의 단일화는 부분적이다.** 형식이 다른 다섯 곳을 기계적으로 합칠 수 없어, 정본 지정과
  일치 검증에 그친다. 표류 가능성은 남는다.
- 지적 4의 "제거 기준"은 문서일 뿐 강제력이 없다. fablize처럼 측정으로 뒷받침하려면 별도 타스크다.
- 커밋 정책 변경(지적 7)으로 이전에 무시되던 파일들이 한꺼번에 추적 대상이 된다. 첫 커밋이 크다.
