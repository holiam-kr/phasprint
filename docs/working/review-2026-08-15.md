### 대조에서 얻은 결정적 사실 3가지

**(가) 상태 머신의 실제 비용 — OMC가 실증**

OMC는 "명시적 상태 파일" 설계를 실제로 구현했고, 그 대가가 코드에 남아 있다:

```
state-tools.ts:83        CANCEL_SIGNAL_TTL_MS = 30_000
persistent-mode.cjs:285  TEAM_PIPELINE_STOP_BLOCKER_TTL_MS = 5분
persistent-mode.cjs:287  RALPLAN_STOP_BLOCKER_TTL_MS = 45분
persistent-mode.cjs:466  AWAITING_CONFIRMATION_TTL_MS = 2분
persistent-mode.cjs:272  "States older than this are treated as inactive to prevent stale state"
state-tools.ts:687       "state mutation lock unavailable"  — 쓰기 락
state-tools.ts:859       "completed-session orphan state file"  — 고아 상태 수거
```

전부 **LLM이 상태를 안 지웠을 때**를 방어하는 장치다. OMC plan 스킬(`skills/plan/SKILL.md:92`)이
그 실패를 직접 경고한다:

> Without cleanup, the stop hook blocks all subsequent stops ... **even after the consensus
> workflow has finished.**

→ **상태 머신은 채택하지 않는다.** 15파일 플러그인이 감당할 비용이 아니다.
fablize는 정반대로 **매 프롬프트 리셋**(`gate_prompt.py`)으로 상태를 없앴고 TTL이 하나도 없다.

**(나) 판정 근거는 텍스트가 아니라 관측이어야 한다**

`verify_state.py` 주석 원문:

> The decision is made purely from observed ledger state — **never from the assistant's claim
> text** — so it is language-agnostic.

fablize는 `PostToolUse` 로 실제 도구 결과를 적립하고 Stop에서 그 원장만 본다.
OMC도 `post-tool-verifier.mjs` 를 건다. **phasprint에는 `PostToolUse` 훅이 없다** —
Evidence 규칙이 프롬프트 부탁으로만 존재한다.

**(다) fail open은 조용하면 안 된다**

```python
except Exception as exc:  # fail open
    emit_json({"systemMessage": f"fablize gate stop hook failed open: {exc}"})
```

fablize 훅 3개 전부 이 패턴. phasprint는 catch 11곳이 전부 공백이라 지적 2의 원인을 못 찾았다.

**근거** — 이번 세션 실측. 계획서를 쓴 직후 `gate.cjs` 가 매 턴 출력:

through to completion ... Do not seek approval again between steps.

`Stop` 훅도 실제로 차단했다. 그 문구(`finish-gate.cjs:98-99`)는 정당한 중단 사유 5개를

**근본 원인** — 승인 상태가 기록되지 않는다. `activePlans()` 는 `task_*.md` 를 glob 할 뿐.

`docs/plans/draft/` → `approved/` → `archives/`. `activePlans()` 는 `readdir(approved/)`.

대조 근거: OMC는 아티팩트 마커(`pending approval`, `handoff-policy: approval-required`)와
상태 파일을 **두 겹**으로 쓴다. 훅이 차단을 강제하기 때문. phasprint의 훅은 넛지만 하므로
첫 겹으로 충분하다. 상태 머신은 (가)의 비용 때문에 기각.

발화·반복이 컨텍스트를 노이즈로 채워 장기 세션 주의력을 분산 → 하네스가 오히려 마이너스

기각(픽스처·문서 손상 위험). 자기 로그·기록 마스킹 범위로 한정.

### 19. 계획서에 대안 검토가 없다  *(신규)*

현재 템플릿은 `Goal / Scope / Steps / Risks` — 무엇을·어떤 순서로만 담고 **왜 이 방법인지**가
없다. OMC plan 스킬은 **RALPLAN-DR** 로 필수화한다: 원칙 3~5, 결정 동인 top3,
**선택지 2개 이상**(하나뿐이면 기각 근거 명시), 최종 산출물에 **ADR 절**
(Decision / Drivers / Alternatives considered / Why chosen / Consequences / Follow-ups),
deliberate 모드에서는 **pre-mortem 3 시나리오**.

폐기한 `task_001` 의 `## Design` 절이 정확히 이 자리다 — 두 하네스가 독립적으로 같은 결론에
도달했고, OMC도 **별도 게이트 없이 계획서 안에** 넣었다.

`commands/go.md:7` 은 인자 없음·복수는 다루지만 0건은 안 다룬다.

### 15. 한국어 트리거가 스킬에만 있고 커맨드에는 없다
`commands/*.md` description은 영어 전용. 대조군은 fablize `classify_task.py` 가 한국어 정규식을
코드에 넣고, OMC·가재코드는 README를 12개/4개 언어로 낸다.

### 16. `plugin.json` 메타데이터 빈약
`homepage`·`repository`·`license`·`keywords` 없음. MIT `LICENSE` 파일은 있는데 미선언.

### 17. 커맨드 본문의 `${CLAUDE_PLUGIN_ROOT}` 치환 여부 — unverified
훅에서는 동작 확인. `commands/*.md` 본문은 여전히 미확인.

**rev.3 조사 결과** — Anthropic 공식 플러그인이 커맨드 본문에서 이 변수를 쓴다
(`claude-plugins-official/plugins/code-modernization/commands/*.md` 의
`scriptPath: "${CLAUDE_PLUGIN_ROOT}/workflows/..."`). 다만 그건 스크립트 러너에 넘기는
인자이고, phasprint 처럼 **모델이 읽을 경로**로 쓰는 용법과 다르다.

주목할 대조 — OMC는 커맨드 본문에 폴백 문장을 단다: *"If the file is not directly readable
from the current working directory, locate it under the active `CLAUDE_PLUGIN_ROOT` ...,
then continue."* 6,000파일짜리 하네스가 치환을 그냥 믿지 않는다는 뜻이다.

**수정 방향** — 치환 확인을 기다리지 말고 OMC식 폴백 한 줄을 세 커맨드에 넣는 것이 싸고 안전하다.
(`task_002` 범위 밖이라 넣지 않았다.)
**확인 방법** — 세션에서 `/plan` 을 실제 실행하고 스킬 본문을 읽어 오는지 관찰.

### 18. 스킬 문서에 공통 스키마가 없다  *(신규)*
OMC는 40개 스킬에 11개 섹션 고정 스키마를 적용한다: `<Purpose>` `<Use_When>`
`<Do_Not_Use_When>` `<Why_This_Exists>` `<Execution_Policy>` `<Steps>` `<Tool_Usage>`
`<Examples>`(Good/Bad) `<Escalation_And_Stop_Conditions>` `<Final_Checklist>` `<Advanced>`.
phasprint의 두 스킬은 구조가 제각각이고 **안티트리거도 예시도 없다.**

### 20. 품질 기준이 정성적이다  *(신규)*
sprint는 "테스트·lint 통과"로 끝난다. OMC는 수치로 못박는다 — **주장 80% 이상이 파일/라인 인용,
수용 기준 90% 이상이 테스트 가능, 모호어 금지("fast" → "p99 < 200ms")**.
